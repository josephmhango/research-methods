\subsection{Basic data types in R}\label{basic-data-types-in-r}

R works with different kinds of \textbf{data objects}, and each object
has an associated \textbf{type}. These types determine what operations
are possible and how the data is treated during analysis. All the data
you create lives in the \textbf{Global Environment}, and it's important
to know what kind of data you're working with.

R is pretty good at guessing what type your data should be --- but this
can sometimes backfire. Think of R as a \emph{passive-aggressive
butler}: it tries to help, but doesn't always tell you when it's done
something ``helpful.'' So, you should learn to check and control data
types explicitly.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{Special values in R}\label{special-values-in-r}

There are a few special types of values that you'll come across often:

\begin{itemize}
\tightlist
\item
  \texttt{NULL} means an undefined or empty object (a missing vector).
  Use \texttt{is.null()} to test it.
\item
  \texttt{NA} stands for \emph{Not Available} and represents missing
  data. Check with \texttt{is.na()}.
\item
  \texttt{Inf} and \texttt{-Inf} mean positive or negative infinity
  (e.g., from \texttt{1/0}). Use \texttt{is.infinite()}.
\item
  \texttt{NaN} means \emph{Not a Number}, e.g.~\texttt{0/0}. Use
  \texttt{is.nan()}.
\end{itemize}

\subsection{Naming objects in R}\label{naming-objects-in-r}

There are some general rules and conventions for naming objects in R:

\begin{itemize}
\tightlist
\item
  Names must start with a letter.
\item
  Names can include letters, numbers, underscores (\texttt{\_}), and
  dots (\texttt{.}).
\item
  Avoid special characters like \texttt{@}, \texttt{\%}, \texttt{\#},
  etc.
\item
  Avoid spaces --- use underscores or camelCase instead.
\item
  Use names that are short, descriptive, and consistent.
\end{itemize}

\subsection{Data with factors}\label{data-with-factors}

Factors are how R represents \textbf{categorical data}. This is useful
when you have data that falls into named categories, such as treatment
groups, soil types, or crop varieties.

Let's say you want to analyse categorical data. Sometimes this is called
a \emph{factor}.

\includegraphics{pics/mean_mark_boxplot_ggplot2.webp}

There are two types of factors:

\begin{itemize}
\tightlist
\item
  \textbf{Unordered (nominal)}: No implied order among categories.

  \begin{itemize}
  \tightlist
  \item
    Example:
    \texttt{cow\_names\ \textless{}-\ factor(c("Martha",\ "Ruth",\ "Edith"))}
  \end{itemize}
\item
  \textbf{Ordered}: There is a logical order.

  \begin{itemize}
  \tightlist
  \item
    Example:
    \texttt{dose\ \textless{}-\ factor(c("Control",\ "Half",\ "Full"),\ ordered\ =\ TRUE)}
  \end{itemize}
\end{itemize}

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{Vector and Matrix fun}\label{vector-and-matrix-fun}

These are the fundamental data containers in R. They organise values in
structured ways:

\begin{itemize}
\tightlist
\item
  \textbf{Vector}: One-dimensional, holds values of the same type.
  Indexed as \texttt{my\_vec{[}i{]}}
\item
  \textbf{Matrix}: Two-dimensional, also holds only one type. Indexed as
  \texttt{my\_mat{[}i,\ j{]}}
\item
  \textbf{Array}: Extends matrix to 3+ dimensions, indexed as
  \texttt{my\_array{[}i,\ j,\ k{]}}
\end{itemize}

\subsection{Lists}\label{lists}

Unlike vectors and matrices, \textbf{lists} can contain elements of
different types. This makes them ideal for storing heterogeneous
information such as model outputs, metadata, or complex data structures.
